How Llama 3.2 1B learns to pick trading tools

Real trader questions from a private set go in at the top. Muse Spark runs the agent loop against the mock market, traces are kept only when their tools match the expected ones, and the agent framework fine-tunes Llama 3.2 1B on them. The adapter that passes the eval gate is served to the phone and published. Every live turn is logged and feeds the next round of traces.

Step by step

#StepWhat happens
1Trader questionsReal spoken trading questions, reviewed by hand, each labelled with the tools it needs from the 14 public tools. Multi-tool questions are composed from pairs. The set stays private.
2Train poolTrain rows get spoken-style paraphrases that keep their meaning, capped at 3,000. Follow-up questions get real earlier turns. The 238 test questions never enter training.
3Muse Spark teachermuse-spark-1.3 picks tools step by step and writes the spoken answer as a template with {slots}. It never sees a real number. Every call is checked against the tool list before it runs.
4Mock market + toolsA seeded generator: 57 tickers, portfolio, Black-Scholes option chains, news and events. The same seed gives the same day, so traces and evals repeat exactly.
5FiltersA trace is kept only if its tools, arguments, step count and action match the gold label and its answer uses only real slots.
6SnapshotThe framework's renderer hook writes each trace in Llama 3.2's chat format: one example per decision, parallel calls in one step, loss only on the model's own tokens. 5% of train groups are held out for validation.
7LoRA trainingLlama 3.2 1B Instruct, bf16, rank 16 on all layers, 3 epochs, cosine learning rate, best validation checkpoint kept. About an hour on the Mac Studio.
8Eval gateThe 238 frozen questions run live against the tools. Scored on tool choice, arguments, steps, action, answer contract and latency, against base Muse Glimmer and the Glimmer adapter.
9-10Voice loopPhone audio → Whisper → Llama picks tools → code validates and runs them → answer template → code fills the numbers → Kokoro speaks. Orders only become tickets that need confirmation.
11AdapterThe weights are public. The question set, its labels and the eval questions stay private.
12Live test logEvery turn is saved with its tool calls and timings. Misses such as Oracle heard as OR, or a strike left out of a chain answer, become targeted rows for the next Spark round.

The model never sees numbers

Tools return judgment words and slot names. The model writes "You're {direction} {pnl} on NVDA", and code fills in the values. A trained model can't make up a price.

Why a 1B student

A voice answer has to start fast. On the same test, the 30B Glimmer took about 4 seconds per answer; a 1B model trained on the same traces answers in well under a second on the Mac Studio.

Spend
